## 1. 今日最值得关注的进展

### 1.1 Unsiloed AI：把企业复杂文档变成 Agent 可验证的数据，并尝试直接向 Agent 销售服务

- **发布日期：** 2026-11-18
- **重要性：** A
- **领域/类型：** AI × Data Engineering、AI Agent、Vertical AI；创业公司/融资/商业产品
- **解决的问题：** 企业知识大量存在于 PDF、扫描件、表格、图表、合同、财务报表和行业文档中。普通 OCR 解决的是文字识别，通用 LLM 直接读文档又容易丢失表格层级、单位、脚注、跨页关系和领域语义。Unsiloed 把这些内容转成可供 Agent、Vector DB、Warehouse 使用的 JSON/Markdown/结构化字段，并保留字段来源。
- **团队与背景：** 联合创始人 Aman Mishra、Adnan Abbas 为 IIT Kharagpur 校友；公司参加 Y Combinator Fall 2025。TechCrunch 报道其完成 750 万美元 Seed，由 Felicis 领投，Y Combinator、Orange Collective、Uncorrelated Ventures 及天使投资人参与；团队约7人。
- **核心技术与架构：**
  1. Dual-stream vision model：文本 Token 与图像 Token 分开处理，避免只依赖 OCR 文本流。
  2. Heat-map-based chunking：把更多计算资源分配给表格、数字、图表、签名、脚注等高风险区域。
  3. Domain-specific decoder：利用行业术语和文档上下文区分相同词语在不同业务中的含义。
  4. 三类能力可单独或串联：Parse（结构化解析）、Extract（按 JSON Schema 抽取字段）、Split（拆分多文档和可检索片段）；支持 S3、SharePoint、Google Drive、Snowflake、DMS 等数据入口，并输出给 LLM、Agent、Vector DB 或 Warehouse。
  5. 输出包含 confidence score，且可选 source citation，便于人工复核后再进入下游业务系统。
- **成熟度与商业验证：** 官网提供自助试用和按页计费，未标注明确 GA 版本。当前公开价以 Credits 计费：1美元购买1,000 credits；Parse Fast 为每千页5美元，Parse Agentic Lite 为15美元，Parse Agentic Pro 为40美元；Extract Agentic Lite/Pro 分别为40/100美元，Split 为10美元，Classify 为5美元。Growth/Enterprise 为定制价格，提供 Zero Data Retention、HIPAA BAA、SSO/SAML、数据驻留，以及 VPC、On-prem、Air-gapped 部署选项。
- **Agent 经济的新信号：** 官网首页和 Pricing 页面明确展示面向 Agent 的 Storefront，提供 llms.txt、实时价格和支付说明；公司称 Agent 可以自主购买，也可以先取得 Human Approval，并可在同一流程中设置支付方式。这是值得跟踪的 Agent-to-Service/B2A 分发模式，但本次无法独立验证完整支付流程，也不应把它等同于通用 Agent 支付标准。
- **实验与证据质量：** 公司向 TechCrunch 提供的客户测试称，在542份金融文档、约84,000个数据点上达到99.78%准确率；公司自行运行的 olmOCR-Bench（1,403页）得分88.0，高于其对比的 GPT-5.5 84.6、Claude Opus 4.7 81.9、Gemini 3 Pro 77.7、Reducto Agentic 66.0 和 Unstructured 39.9。以上均为公司提供/自测数据，TechCrunch 明确指出未获独立验证，不能当作第三方结论。
- **客户与竞品：** 创始人称金融、法律、医疗领域已有客户，并点名语音 AI 公司 Bolna AI；银行和律所客户未具名。主要替代方案包括 Reducto、Unstructured、LlamaParse、Azure Document Intelligence、AWS Textract，以及直接使用通用多模态模型。
- **独立判断：** 这是一个值得跟踪的 Agent Data Layer 创业方向：Agent 的上限不仅由模型决定，也取决于输入文档能否被稳定解析、字段能否回溯到原文、低置信度结果能否进入人工复核。Dual-stream 与 heatmap 的实质价值需要在跨客户、跨行业的盲测中验证。短期风险是团队规模小、竞争者多、基准结果未独立复现；长期护城河更可能来自行业文档数据、错误反馈闭环和企业工作流集成，而不是单一模型结构。

### 1.2 Pedestal AI：供应链 Agent 从预测走向履约执行，出现可量化的企业运营案例

- **发布日期：** 2026-11-17（从 Stealth 发布并宣布融资）
- **重要性：** A
- **领域/类型：** AI Agent、Vertical AI、AI × Data Engineering；创业公司/融资/客户部署
- **解决的问题：** 零售、制造和物流的业务状态分散在 ERP、TMS、WMS、邮件和员工经验中。传统分析系统能够预测延误，却不一定能主动完成客户联系、订单录入、异常处理和运输协调。Pedestal 的目标是让 Agent 在现有系统和权限范围内完成这些操作。
- **团队与背景：** 公司位于 Boston；CEO/联合创始人 Raj Aggarwal 曾任 AWS Generative AI General Manager，并与 Localytics 联合创始团队共同创业。公司宣布完成470万美元 Seed，Eclipse 领投，RRE、Converge、Timescale Ventures、VitalStage Ventures 参与。
- **核心技术与架构：**
  1. 从 ERP、TMS、WMS、邮件读取业务状态；
  2. 将企业数据、员工/SME 经验和行业知识结合，形成可供 Agent 继承的业务上下文；
  3. 在既有系统中执行客户电话/SMS、订单处理、运输协调、异常提醒、运营报告等工作；
  4. 官网称可运行在客户自己的 Cloud、VPC、On-prem 或 Data Warehouse 环境，沿用客户访问控制并记录 Agent Action。
- **商业验证：** 11月17日融资公告称：一家 Fortune 500 电商企业使用 Agent 每天发起数千次配送协调电话，未送达率下降20%；北美大型图书印刷商将订单处理时间降低90%；一家全球物流公司用其回答客户报关和运输问题。公司官网另称其产品已在零售、制造和运输企业运行，并展示 Wayfair、US Farathane、Marcal、RESRG Automotive、Lakeside Book Company、Matson 等客户/案例标识。
- **指标与口径限制：** 公司官网不同页面对零售配送案例出现20%与25%两种未送达率改善数字；不同页面还分别出现1.5M deliveries/year 与4M packages/month 两种规模描述，页面没有解释它们是否对应不同客户、不同时间段或不同统计口径。另一全球承运商案例宣称97%+准确率。所有数字均为公司自述，尚无第三方审计。
- **定价与成熟度：** 官网当前销售页面写明可在约1个月内完成生产上线，报价区间25,000—50,000美元；但没有说明该金额是实施费、首期项目费还是完整合同价格。官网称 SOC 2 Type II、支持 VPC/On-prem 和 Action Log，尚未取得独立审计报告进行核验。
- **竞品/相关方案：** 与 Atomic（库存/供应链优化）、Loop（预测分析）、传统 TMS/WMS、RPA 和通用企业 Agent 有交叉，但 Pedestal 更强调从业务数据到操作执行的闭环。
- **独立判断：** 这是比“Agent 能回答问题”更有商业意义的方向：电话、短信、订单录入和异常处理都能映射到履约指标。真正的壁垒是对 ERP/TMS/WMS 的深度集成、业务规则与员工隐性知识建模、动作可审计，以及错误动作的责任边界。当前最大缺口是没有公开模型选择、Agent Evaluation、失败回滚和权限策略细节；20%/25%指标差异也需要澄清。值得继续跟踪客户复购、部署扩展和单位经济性。

### 1.3 LianLian XWorker：跨境商业 Agent 接入支付身份和 Tokenized Credential，Visa 确认一次真实 B2B 交易

- **发布日期：** XWorker 于2026-11-19发布；Visa 交易公告于2026-11-18
- **重要性：** A
- **领域/类型：** AI Agent、AI 应用、Agentic Commerce、FinTech；产品发布/商业验证
- **解决的问题：** 跨境电商运营涉及选品、市场研究、商品上架、多语言营销、客户服务、采购和财务对账。Agent 如果只能生成建议，仍需要人逐步切换业务系统；如果要执行采购或付款，则必须解决身份、授权、额度和支付安全。
- **团队与背景：** 产品由连连数字推出。此次重点不是新模型，而是把 Agent 工作流与跨境支付能力结合。
- **核心技术与架构：**
  1. XWorker 定位为 AI Workforce，提供云端持续运行环境、多 Agent 协作、任务拆解、审批、可复用 Skills/Memory。
  2. 公司称 RouterBrain 可路由300多个模型。
  3. Agent Wallet、XPay、XCard 将 Agent 身份、支付权限和支付工具接入业务流程；XCard 面向符合条件的客户申请。
  4. Visa Intelligent Commerce Connect 和 Visa Agentic Directory 为 Agent 交易提供注册、Tokenized Credential 和支付连接。
- **商业验证：** Visa 公告确认完成一笔真实 B2B Agentic Commerce 交易：Agent 通过 Visa Agentic Directory 注册，使用 Tokenized Credential，经 Visa Intelligent Commerce Connect 完成办公用品采购。这比概念 Demo 更进一步，但仍是一笔受控交易，不代表大规模商用或通用采购 Agent 已成熟。
- **成熟度与商业模式：** XWorker 已发布，但具体客户接入方式仍以申请为主；XCard 面向符合条件的客户。未披露 XWorker 定价、交易量、活跃 Agent 数或持续付费客户数。
- **竞品/相关方案：** Visa 的 Agentic Commerce 基础设施、其他支付网络的 Agent Tokenization、企业采购系统和通用 Browser/Computer-use Agent。差异点在于将 Agent 执行与支付身份/支付工具打通，而不只是网页自动化。
- **独立判断：** Agentic Commerce 的关键不在“Agent 能否点击购买”，而在于能否把 Agent 身份、委托授权、单笔/累计额度、商户范围、Token 生命周期、撤销、幂等、退款、拒付和审计纳入支付协议。Visa 已确认一次交易，说明支付网络开始提供基础设施；但距离跨商户、跨平台、可撤销和可追责的生产级采购仍有明显距离。

### 1.4 数据库版本窗口：PostgreSQL 19 GA 与 DuckDB 2.0.1 LTS Patch 都在解决生产级正确性和运维风险

- **发布日期：** PostgreSQL 19 于2026-11-19 GA；DuckDB 2.0.1 于2026-11-20发布
- **重要性：** A
- **领域/类型：** Database × Storage、Database Operations；版本发布
- **PostgreSQL 19：**
  - 新增 REPACK，支持在大部分重建过程中保持正常读写；相比 VACUUM FULL/CLUSTER，减少长时间独占锁的影响。注意仍需要额外磁盘空间和 Replication Slot，最终切换阶段仍会短暂取得 ACCESS EXCLUSIVE Lock；官方说明 Concurrent Repack 不是 MVCC-safe，不能不经评估直接用于所有生产表。
  - 新增 pg_plan_advice / pg_stash_advice，允许对特定 Query ID 保存并应用 Plan Advice。它们不是替代 Cost-based Optimizer，也不意味着强制计划一定更快；仍需按真实工作负载验证。
  - 新增 WAIT FOR LSN，为 Standby 提供 Read-your-writes 同步点；连接池或应用仍需把 Primary 的 LSN 传递给 Replica。
  - Logical Replication 改进包括 Sequence 同步、无需重启即可激活 Logical Decoding 的路径，以及更多冲突诊断能力。
  - Parallel Autovacuum、IO/WAL 统计、postgres_fdw 远端统计导入和 INSERT ... ON CONFLICT DO SELECT 等也值得关注。JIT 默认关闭，MD5 密码认证继续被弃用并发出警告。
- **DuckDB 2.0.1：**
  - 这是 2.0 LTS 的第一个 Patch Release，不是普通的微小修复。修复特定 Linux Kernel 与 MADV_FREE 组合可能导致的静默内存归零/数据丢失风险；DuckDB 随附的 jemalloc 将 muzzy_decay_ms 设为0规避该问题。
  - 修复读取 DuckDB 1.x 数据库时过滤含 NULL 行可能漏行的问题；修复 WAL Replay 后索引项丢失、重启后数据行丢失等 Storage/Transaction 问题。
  - 修复 enable_external_access=false 时仍能 CREATE SECRET 的安全边界缺陷，并修复远程路径穿越及 Brotli Decoder CVE。
  - 2.0.0 对 UPDATE ... FROM 和 MERGE 的行为变化在 2.0.1 中恢复为 1.x 语义：多个 Source Row 命中同一 Target Row 时会逐匹配更新，最终值可能不确定。升级前必须检查 Source Key 唯一性和业务预期。
  - DuckDB 1.4 LTS 社区支持于11月17日结束；2.0 LTS 至少支持到2027年10月。
- **独立判断：** DuckDB 2.0.1 的优先级高于普通 Patch：涉及数据丢失、事务可见性、索引持久化和安全开关。生产用户应先核对 Linux Kernel、External Access、SECRET Scope、UPDATE FROM/MERGE 语义和旧库兼容性，再安排升级。PostgreSQL 19 的核心价值是运维可控性、复制一致性和计划稳定性，而非单一性能革命；升级仍需验证 Extension、执行计划和默认值。

  - [PostgreSQL Global Development Group：PostgreSQL 19 Released](https://www.postgresql.org/about/news/postgresql-19-released-3449/)
  - [Neon：Postgres 19 新特性与升级注意事项](https://neon.com/blog/postgres-19-is-out-try-it-on-neon)
  - [DuckDB：Announcing DuckDB 2.0.1 LTS](https://duckdb.org/2026/11/20/announcing-duckdb-201)

### 1.5 学术雷达：Errpedia 与 MoL-SQL 把 Agent 数据访问中的两类隐蔽正确性问题变成可测基准

- **发布日期：** 两篇论文均于2026-11-17提交 arXiv
- **重要性：** A
- **领域/类型：** Database、Vector Search、Text-to-SQL、AI × Data；学术预印本
- **论文状态：** 均为 arXiv v1 预印本，本次未发现正式录用或同行评审信息。作者实验结果不能等同于第三方复现或生产环境证据。

**A. Errpedia: Is Your Exact k-NN Vector Search Really Exact?**

- **作者/机构：** Yinuo Deng、Ying Zhang、Hanchen Wang、Wenjie Zhang；论文列出 UNSW 与 University of Technology Sydney 研究团队。
- **研究问题：** 即使数据库或向量库声称执行 Exact k-NN Search，浮点舍入、溢出和边界条件仍可能导致 Top-k 排序错误、结果不完整，进而污染 ANN 的 Ground Truth 和下游 RAG/Agent。
- **方法与实验：** 构造1,616个查询、21类数值错误场景；使用 Exact Rational Arithmetic 生成 Ground Truth；评测20个 Library/Database 配置，覆盖 Faiss、scikit-learn、SciPy、Milvus、Qdrant、Weaviate、LanceDB、ClickHouse、DuckDB、TiDB、MariaDB、pgvector、Elasticsearch、OpenSearch、Solr、Redis、Dragonfly、MongoDB、Neo4j、SurrealDB 等。测试集合包含22,501个128维向量，重点检查 k=10 的精确结果。
- **作者结论：** 每个被测配置至少在一个适用查询上返回数学上不正确的 Top-10。错误包括近似等距向量误排序、返回少于 k 个邻居，甚至遗漏全部10个精确邻居。
- **局限：** 这是专门构造的数值边界压力集，不是生产数据分布；不能据此推断这些系统的日常检索普遍不正确。论文不是延迟/吞吐 Benchmark，也不是全版本、全配置穷举。GitHub 仓库当前可见内容以数据文件为主，约72MB base.csv；未发现完整可运行评测 Harness、README 或明确 License，复现门槛仍高。
- **价值判断：** 值得向 Vector DB 和 RAG 系统引入数值正确性回归测试；Exact Search 不能仅靠 API 名称或产品文档认定正确。

**B. MoL-SQL: A Controlled Benchmark for Mixture-of-Language Text-to-SQL**

- **作者：** Tianqi Luo、Boyan Li、Yuyu Luo。
- **研究问题：** 现实企业数据中，用户问题、Schema 标识符和数据库 Stored Values 可能使用不同语言。只把问题翻译成目标语言，并不能解决 Schema/Value Entity Mapping。
- **方法与数据集：** 在5个既有 Text-to-SQL 数据集上构建对齐版本；MoL-Full 包含16,892个样本，MoL-Cube 包含3,840个样本，通过独立切换 Question、Schema、Stored Values 的语言，保持任务意图和 SQL 结果语义不变。实验覆盖8个 LLM 和4类 Text-to-SQL 方法。
- **核心结果：** Schema 语言和 Value 语言产生不同影响；中文 Schema 在多种问题语言设置下更难，而英文问题匹配中文 Stored Values 时，执行准确率最多下降23个百分点。额外翻译或增加推理步骤没有消除 Value Gap；访问目标数据库中的实际值并做 Context Grounding 能显著缩小差距。
- **局限与 Artifact：** 主要研究英中语言组合，数据库状态以 SQLite 迁移版本为准；论文明确不声称在所有数据库状态下保持语义等价。代码与数据已公开，但仓库未见顶层 License，最近可见提交时间较早；本次未发现第三方复现。
- **价值判断：** Text-to-SQL 和 Data Agent 的问题不只是 SQL 生成能力，更是数据库内实体、缩写、行业术语和实际取值的跨语言 Grounding。企业 Data Agent 应把值域检索、实体映射、Schema 语义和 SQL Execution Verification 作为独立模块，而不是只增加 Prompt 或模型推理预算。

- **原始资料：**
  - [Errpedia arXiv:2611.22474](https://arxiv.org/abs/2611.22474)
  - [Errpedia 数据仓库](https://github.com/dynos01/errpedia)
  - [MoL-SQL arXiv:2611.22333](https://arxiv.org/abs/2611.22333)
  - [MoL-SQL 代码与数据](https://github.com/MoL-SQL/MoL-SQL)

## 2. 今日产业与学术判断

1. **Agent 的商业价值正从“会回答”转向“能执行且可追责”。** Unsiloed 把文档数据转成可验证字段，Pedestal 把 Agent 放进物流和 ERP 工作流，LianLian 把 Agent 接到支付身份和 Tokenized Credential。产品的核心不再是模型是否会规划，而是数据、权限、事务、回滚、支付和审计能否闭环。
2. **Agent Data Layer 正在独立成层。** 企业文档解析、业务上下文、Schema/Value Grounding、来源追踪和低置信度复核，开始成为独立产品，而不是简单塞进 RAG 或 Prompt。Unsiloed 的文档结构化与 Pedestal 的业务知识层是两种不同实现路径。
3. **数据正确性会成为 Agent 进入生产环境的基础门槛。** DuckDB 2.0.1 的 Storage/Transaction 修复、PostgreSQL 19 的复制一致性和计划控制，以及 Errpedia/MoL-SQL 揭示的向量检索和跨语言实体映射问题，说明模型推理正确不等于数据访问正确。
4. **AI Infrastructure 厂商正从 GPU/Inference 扩展到 Agent 平台和企业应用。** OVHcloud 11月19日公布55项 Cloud/AI 产品，覆盖 GPU、AI Fabric、AI Agents、AI Search 和 OVHai Workspace，并与 Qwant、Shadow、EUSP 连接欧洲 Search Index、模型和算力。战略方向清晰，但多数 AI PaaS/AI SaaS 产品仍处于 Alpha，不能把产品目录规模等同于生产成熟度。

## 3. Agent 专项观察

**本日 Agent 专项有多项可靠新增；Memory 专用数据库和独立长周期 Agent Benchmark 未发现达到重点入选标准的新进展。**

### 产品与企业应用

- **InstaLILY Lily for Sales（11月19日，Early Access）：** 面向分销商、制造商和工业供应商的 B2B Sales Agent。每个销售机会拥有一个持久化 Room，Account Agent 检查合同和客户要求，Product Agent 匹配产品，Pricing Agent 应用合同价格，Skeptic Agent 对方案提出质疑。Dynamics 365 仍是 System of Record，运行在 Azure；产品称只有负责人批准后才会向客户发送内容或写入 Dynamics 365。InstaLILY 称正在集成 NVIDIA OpenShell，为每个 Agent 限制文件、系统和网络访问并记录决策。新产品目前为 Enterprise Early Access，尚未披露独立客户指标、定价或生产部署规模。公司称由 Amit Shah、Sumantro Das 创立，已从 Energize Capital、Insight Partners、Home Depot Ventures 等投资方融资近1亿美元。
- **OVHai Workspace（11月19日，Public Alpha）：** OVHcloud 推出的企业协作与 Agent 平台。Productivity 空间整合邮件、日历、文档、存储和视频会议；Alpha 免费提供每用户5GB，数据托管在欧洲且不用于模型训练。Knowledge Platform 搜索已可用，采用 Semantic + Lexical Search，厂商称每个 Collection 可覆盖数亿文档；Ontology、企业数据治理和 On-prem Appliance 仍属于后续方向。
- **Pedestal、LianLian：** 见重点进展1.2和1.3；它们分别代表运营履约 Agent 与 Agentic Commerce。

### Agent Platform、SDK 与数据平台

- **Snowflake Cortex Agent SDK 1.0 GA（11月18日）：** Python 与 TypeScript SDK 进入 GA；同周还有 Retrieve Cortex Search GA、AI Governance Preview，以及 Prompt Injection Guardrails 的 LOG Mode。LOG Mode 主要用于观察/记录检测结果，不应误认为已经阻断所有攻击。
- **Snowflake Postgres Token-based Access Roles（11月20日 GA）：** 提供短期 Token 与 Access Role 的数据库访问路径，减少向 Agent/应用共享静态密码的需要；PostgreSQL 对象权限仍由数据库角色控制。这是比直接把账号密码交给 Agent 更可控的身份基础。
- **OVHcloud AI Agents / AI Search / AI Fabric：** 分别覆盖 Agent Host/Connector/MCP、企业文档检索和 GPU 计算编排，但在官方产品目录中均标为 Alpha。厂商称 Agent 平台有近480个 Connector/MCP Server，WebAssembly Sandbox 启动约2ms；这些性能和覆盖数字尚无独立 Benchmark。
- **LangGraph：** 本周观察到1.2.24 Patch 版本；本次未发现足以改变 Runtime/Orchestration 架构的新增，按维护性更新处理。

### Open Source、Runtime 与安全

- **claude-code-hooks：** [GitHub 仓库](https://github.com/karanb192/claude-code-hooks)，MIT License；README 展示22个 Plugin/Marketplace 扩展，近期提交加入 Codex CLI 支持，并自报2,393项测试。覆盖危险命令拦截、敏感信息检查、测试跳过检测和会话记录。重要限制是其 README 明确说明 Hooks 只能检查宿主发送给 Hook 的事件，Pattern Check 不是 Sandbox，也不能替代 OS/Container Isolation；适合作为纵深防御的一层，不适合作为唯一安全边界。
- **NVIDIA OpenShell：** [GitHub 仓库](https://github.com/NVIDIA/OpenShell)。通过 Gateway、Sandbox、Policy Engine 和 Provider Access 管理文件、进程、网络和模型凭证；凭证可绑定到获准 Endpoint，策略变更支持 Formal Verification。仓库提示项目正在向 CNCF/ai-openshell 迁移。InstaLILY 把它作为 Lily for Sales 的 Agent Runtime，值得观察其在真实企业 CRM 工作流中的权限粒度和审计完整性。

### Memory、Evaluation 与商业化

- **Memory/Context：** 本次未发现 Mem0、Letta、Zep/Graphiti 等专用 Memory 项目在近7天有达到入选标准的重大版本/架构发布。Lily Room 和 XWorker 的可复用上下文/Skills 属于应用层持久化工作状态，不等于已经解决跨 Agent 的长期记忆更新、冲突、遗忘和审计。
- **安全与治理：** Citi 的 Online User Agreement 于2026年11月新增 Section H，明确警告用户不要把第三方 AI Agent 用于 Citi Online/Mobile；如果用户提供凭证或允许 Agent 访问，Citi 将把 Agent 的访问和动作视为用户授权，即使 Agent 误解 Prompt、超出授权范围或凭证随后泄露。Citi 保留限制/终止第三方 Agent 访问的权利，并说明 Citi Privacy Notice 不适用于第三方 Agent。TechCrunch 报道 PNC 本周也更新条款，Citizens 向客户发送类似提醒。此处报告的是合同文本和媒体报道，不代表法院已确认其全部条款在任何情形下都可执行；具体权利仍受适用法律约束。
- **商业化验证：** 本周最具体的信号是 Visa 确认的一笔 LianLian B2B Agentic Commerce 交易，以及 Pedestal 的企业运营指标。Unsiloed 则展示 Agent 可直接购买 API 服务的 Storefront。三者分别覆盖 Agent 的付款、业务执行和服务采购。
- **Evaluation/Observability：** 本周未发现新的、可独立复现的长周期 Agent 成功率 Benchmark。厂商客户案例和自测指标应与第三方评测分开记录。

**Agent 专项判断：** 近期 Agent 全栈的关键矛盾是“委托权限如何被表达和验证”。银行条款把错误责任推向用户，而支付网络和数据库厂商开始提供 Tokenized Credential、短期 Access Role、Human Approval 和 Audit Log。未来可扩展的企业 Agent 更可能建立在可撤销的 Scoped Authorization、交易级预算、审计轨迹和事务边界上，而不是共享用户密码并依赖 Prompt 约束。
