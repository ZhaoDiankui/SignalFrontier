## 一、今日最值得关注的5项进展

### 1. Qwen4-Max 正式进入 Model Studio 生产 API：百万上下文与工具调用并行推进

- **发布日期：** 2026-11-16（官方模型文档更新日期；Reuters 同日核实发布）。
- **重要性：** A
- **领域/类型：** AI 应用、Agent、AI Infrastructure / 产业与产品。
- **解决的问题与用户：** 面向企业和开发者提供高上下文长度、多模态输入和工具调用能力，主要通过云 API 使用。
- **核心能力与接口：**
  - Model Studio 的生产模型 ID 为 qwen4-max，支持文本、图像、视频输入和文本输出；上下文窗口为 1,000,000 tokens。
  - 支持 Tool Calling、Parallel Tool Calls、Web Search、Structured Outputs，并提供 OpenAI Chat Completions、OpenAI Responses 和 Anthropic Messages 兼容接口。
  - 最大输出长度按模式区分：非 Thinking 模式 131,072 tokens；Thinking 与最终回答合计最多 262,144 tokens。
  - 官方文档明确：当前 Model Studio 不支持该模型的微调或模型部署。因此这不是可直接下载权重、私有化部署的开源模型交付。
- **价格：** 官方 Model Studio 文档列出的每百万 tokens 价格具有地域差异。例如北京区域输入/输出约为 US$1.413 / US$4.24；新加坡区域约为 US$1.50 / US$4.50。实际成本还需按缓存、批处理和调用区域核算，不能把单一地区报价视为全球统一价格。
- **团队与规模：** Reuters 报道模型总参数规模约 2.4T；该参数规模属于公开报道，不等于独立测得的推理吞吐或质量优势。
- **安全与效果证据：** 阿里方面称其安全代码生成内部评测得分从前代约8%提升至14.7%，并称内部任务成本降低约60%。这两项均为厂商自述，未见独立复现实验、完整工作负载和统计方法，不应当作第三方结论。
- **成熟度：** 生产 API 可用；不支持 Model Studio 微调和模型部署。小型 Qwen4 系列开源权重的后续计划，不代表 Max 本身已开放权重；时间、型号和许可证仍需分别核实。
- **竞品比较：** 长上下文与工具调用使其可进入 Research Agent、Coding Agent 和企业数据 Agent 候选；实际比较应同时考察长上下文召回、工具调用成功率、P95/P99 延迟、缓存命中和端到端成本，而不是只比较参数量或上下文窗口。
- **独立判断：** 这是中国模型厂商在 API 产品化上的重要迭代。百万上下文只有与可靠检索、上下文压缩、缓存和权限隔离配合，才会转化为 Agent 的有效工作记忆；模型本身不会自动解决长任务可靠性。建议优先做同一业务工作负载的成本/延迟/工具调用基准。
- **原始来源：** [阿里云 Model Studio Qwen4-Max 文档](https://www.alibabacloud.com/help/en/model-studio/qwen4-max)；[Model Studio 模型价格](https://www.alibabacloud.com/help/en/model-studio/model-pricing)；[Reuters 报道](https://www.reuters.com/technology/artificial-intelligence/alibaba-unveils-qwen4-max-ai-model-2026-11-16/)。

### 2. Genpact Onyx：把流程知识、Agent 编排和治理打包成企业运营平台

- **发布日期：** 2026-11-16；平台于11月12日的 Agentic Operations Day 对外发布。
- **重要性：** A
- **领域/类型：** AI Agent、Vertical AI、企业应用 / 产业与产品。
- **解决的问题与用户：** 面向财务、风险、供应链、银行、保险和采购等企业运营流程，提供 Agent 构建、运行和治理平台。
- **核心架构：**
  - 以 Process Intelligence Core 为核心，将 Genpact 多年运营过程中沉淀的流程、异常、人工判断和业务边界编码为可复用的运营知识。
  - 通过预置工作流和 Agents 让 Agent 不必只依赖 Prompt 或静态流程图理解业务。
  - Learning Loop 将经人工复核的异常和专家决策反馈到流程知识中。
  - Earned Autonomy 采用渐进式授权：先提出建议、由人工批准，之后才根据表现逐步扩大自主决策范围。
  - 平台强调每次 Agent 动作可治理、可审计、可追溯，并可嵌入客户现有技术栈和数据/AI 基础设施。
- **成熟度与商业验证：** 官方宣布平台可用，首批自有解决方案从 Accounts Payable Suite 开始，也支持为客户构建定制方案。但公开材料没有给出 Onyx 的独立 GA 版本号、API/SDK 细节、价格、客户合同金额或 Onyx 专属生产部署指标。
- **客户证据边界：** 发布活动提及 Advantage Solutions、Wesco、USA Today、Ryan Specialty 等企业代表分享 Genpact Agentic Solutions 的使用情况；官方新闻稿没有逐一证明这些企业已购买或生产部署 Onyx 本身，不能将活动嘉宾名单直接写成 Onyx 客户名单。
- **竞品比较：** 与 LangGraph、Dify 等通用 Agent 开发框架不同，Onyx 的主要差异化不是模型调用或工作流 DSL，而是流程运营知识、行业交付能力和人工监督体系；竞争对象更接近 UiPath、Celonis、ServiceNow、SAP Joule 和 Salesforce Agentforce 的企业流程自动化层。
- **独立判断：** 方向值得关注。企业 Agent 的护城河可能来自流程语义、异常处理和责任边界，而不是 Agent 数量。但 Onyx 的关键验证点是：Process Intelligence Core 是否能跨客户复用、异常反馈是否真正改善下一轮决策、人工审批能否按风险分层，以及 ROI 是否由客户数据证明。当前仍应视为“已宣布可用、商业化证据待核验”，而非已证明规模化成功。
- **原始来源：** [Genpact 官方发布](https://media.genpact.com/2026-11-16-Genpact-Launches-Genpact-Onyx%2C-the-Agentic-Operations-Platform-for-Building%2C-Running%2C-and-Governing-AI-Agents-in-Enterprise-Operations)；[Genpact Onyx 产品页](https://www.genpact.com/solutions/onyx)。

### 3. Poki：面向真实 iPhone 的开源移动 Agent，开始从 MCP 控制转向设备端产品

- **近期版本：** GitHub CHANGELOG 记录 0.4.2 Beta 于2026-11-15发布；主分支合并了 0.4.3 Release PR（21项已审查 PR），但本次核验的是主分支提交，不将其写成已打稳定标签的正式发行版。
- **重要性：** A
- **领域/类型：** AI Agent、Computer Use、移动应用 / 开源项目与产品。
- **解决的问题与用户：** 让 Agent 直接操作用户自己的 iPhone 应用，而不是只控制浏览器或模拟器；目标用户是希望让 Agent 完成移动端多步骤任务的开发者和高级用户。
- **技术与部署形态：**
  - 主产品是安装在 iPhone 上的 App。项目文档称 iOS 27 使用原生服务，iOS 18–26 使用 XCTest 路径。
  - 设备与 MCP 客户端之间通过用户自行部署的 Cloudflare Worker 中继通信；文档称中继不持久化用户数据。
  - 手机端生成 Ed25519 密钥，连接凭据保存在 Keychain；每个客户端可单独撤销。
  - 0.4.3 的代码与测试显示：新安装默认对普通步骤采用 Never Ask；支付、删除和 Wallet 卡片没有“Don't ask again”选项，仍保留人工审批。用户可为其他动作配置审批模式和敏感度。
  - 0.4.3 PR 还移除了可能记录认证请求体的 trace 日志，并加入防泄漏回归测试；未知或矛盾的输入送达回执被视为 unknown，后续动作停止；切换 iPhone 时清除旧设备的 CUA 坐标引用。这些是代码与自动化测试证据，不等于独立安全审计。
  - 项目文档说明屏幕内容会发送到用户配置的模型服务，因此“本地运行 App”不等于屏幕数据不会离开设备。
- **开源与成熟度：** 仓库采用 AGPL-3.0-only，当前仍为 Beta。CHANGELOG 中 0.4.2 Beta 日期明确为11月15日；项目主线活跃；0.4.3 自动化测试覆盖部分安全与输入确认路径，但尚无独立安全审计或跨设备、跨 iOS 版本的第三方可靠性评测。旧的 Poki MCP 源码安装路径已被文档标注为不再更新，当前主线应以 iPhone App 为准。
- **竞品比较：** 与 Browser Use、桌面 Computer Use Agent 相比，Poki 触及移动原生 App 和设备权限；但 iOS 自动化稳定性、系统升级兼容性、App 审核政策、支付和账户安全都更难。
- **独立判断：** 这是值得持续跟踪的新开源产品形态：移动端 Agent 的关键不是“能点击屏幕”，而是设备配对、动作可撤销、敏感操作审批和数据边界。0.4.3 对输入送达不确定性和认证日志泄漏的处理值得肯定；但普通步骤新安装默认 Never Ask 是重要的安全默认值选择，企业部署应明确配置审批模式。仍需检查屏幕内容上传范围、模型供应商数据保留策略、敏感操作审批是否可绕过，以及 iOS 版本升级后的回归测试。
- **原始来源：** [Poki GitHub 仓库](https://github.com/JosssphZhou/poki)；[CHANGELOG](https://github.com/JosssphZhou/poki/blob/main/CHANGELOG.md)；[安全与设备端架构文档](https://github.com/JosssphZhou/poki/tree/main/docs)。

### 4. Graphon Labs 完成 3,500 万美元 Series A：将对象存储、检索和持久记忆合并为一层

- **发布日期：** 2026-11-10。
- **重要性：** A
- **领域/类型：** AI × Storage、Agent Memory、对象存储、Context Infrastructure / 创业与融资。
- **融资事实：** Graphon Labs 宣布完成 3,500 万美元 Series A，由 RRE Ventures 领投，HP、Energy Impact Partners、Hitachi Ventures、Gaia VC 参与；公司称累计融资 4,330 万美元。Wilson Sonsini 的交易公告对融资金额和投资方作了交叉确认。
- **产品与架构：**
  - 公司称底层方法基于 graphons 数学框架，目标是保存跨文本、图像、视频等数据的关系、来源和时间信息。
  - 当前开发者文档把 Graphon 定义为“smart blob storage”：使用类似 S3 的 bucket/object/key 组织对象，写入时自动索引，再通过一个接口执行关键词与语义联合搜索，并可生成带来源引用的回答。

  - 注意：文档称 API 形状类似 S3，不等于已证明完整 S3 协议兼容；公司所称的 Enterprise、Developer、On-Device Memory 三条产品线，也不能直接等同于三者都已 GA。
- **公开评测：** Graphon V1 在 ATM-Bench 公共排行榜上有可查的运行记录：1,013个问题的 QA 分数为81.705%，Recall@10为89.776%。该运行使用 Graphon V1 作为 Memory/Retriever、GPT-6 Astra 作为回答模型、GPT-5-mini 作为评测器；排行榜记录其图构建于10月9日、每个配置仅一轮运行且未做 best-of-N。该结果比单纯厂商宣传更可核查，但仍是公开基准的一次提交，不代表生产环境独立验证。
- **客户证据边界：** 新闻稿称已与 San Francisco 49ers、Hitachi 等企业部署/合作，但引用的 49ers 代表表述是“探索”技术价值，Hitachi Rail 的表述是“评估显示前景”；公开证据尚不足以确认付费生产部署、规模和合同金额。
- **商业模式与成熟度：** 开发者文档、CLI、API 和 MCP Server 可公开访问；公开定价、吞吐/成本 SLA、企业客户付费规模未披露。Agent Memory 页面目前是用例文档，不能仅凭页面标题认定完整产品能力已达到 GA。
- **竞品比较：** Mem0、Zep/Graphiti、Letta 更偏 Agent Memory 数据模型和 SDK；Pinecone、LanceDB、Elasticsearch 更偏检索层；S3/R2/GCS 是对象存储层。Graphon 的差异化是试图将对象存储、索引、混合检索和带来源回答合并，而不是只做一个向量库。

### 5. 学术研究：数据库历史记忆与 Agent Harness 开始出现可验证的结构化方法

**5A. MEM-SQL：从已验证 SQL 历史构建可复用的数据库记忆**

- **首次提交：** 2026-11-13；arXiv 预印本，尚非同行评审论文。
- **作者机构：** 香港大学 NICE Lab、新加坡国立大学、香港科技大学（广州）。
- **研究问题：** 现有 Text-to-SQL 基准通常将每个问题独立评估，但真实业务会反复查询同一数据库；过去已验证的 SQL 可以复用 JOIN、聚合和业务口径，却也可能因新问题的条件变化而产生语义错误。
- **核心贡献：** 提出 HARE Benchmark，包含1,600个请求、823条已验证历史查询，来源包括 Spider、BIRD、Spider 2.0 和 BEAVER；MEM-SQL 将记忆分为完整查询模板、可复用 SELECT 组件、Schema 概念三层。每层执行 coverage gate，要求问题所需的每个证据原子都达到阈值；若证据不完整，再按需执行 Schema Linking，最后进行数据库 dry-run。
- **实验：** 六个模型上，平均执行准确率从 Direct Generation 的37.1%提高到50.0%，输入 tokens 减少76.6%，端到端延迟降低68.8%；作者报告平均95.4%的请求可直接由记忆完成。
- **局限：** 多条历史查询组合仍是明显瓶颈，相关子集准确率从56.7%降至29.7%，尤其在需要重组查询结构或共享 JOIN 时。结果为作者实验，未见公开代码/Artifact 链接，也没有第三方复现。
- **独立判断：** 其价值不在“让 LLM 记住 SQL”，而在于把历史查询拆成可验证的计算结构，并显式检查证据是否覆盖需求。这种思路可扩展到企业语义层、Metric Store 和受控 Data Agent。
- **来源：** [arXiv 页面与全文](https://arxiv.org/html/2611.18338v1)。

**5B. VelServe：按真实尾延迟校准推理调度，而不是只按平均延迟或静态 token budget 调度**

- **首次提交：** 2026-11-13；arXiv 预印本，尚非同行评审论文。
- **作者机构：** Sprinklr、Microsoft。
- **研究问题：** Decode jitter 会让同一批正在生成的请求同时出现 token 间隔超时；即使使用 chunked prefill 或 Prefill/Decode disaggregation，接纳新请求的 iteration 仍可能超过 TBT SLO。
- **方法：** VelServe 用最近迭代的真实残差分布校准 tail margin，按每次 iteration 的延迟尾部限制 prefill 工作量；再采用 shortest-remaining-prompt-first 恢复 TTFT；在 P/D disaggregation 下控制新请求进入 decode 的节奏。实现为 vLLM V1 scheduler 插件，论文称约1,000行 Python，复用现有 batching、KV allocation、CUDA Graph 和异步调度。
- **实验环境：** 聚合部署使用1×NVIDIA H100 NVL 94GB HBM3、vLLM 0.30.0、CUDA 13、PyTorch 2.13；模型包括 Qwen3-8B、DeepSeek-V2-Lite、DeepSeek-V4-Flash。工作负载覆盖128至120k tokens 的 Prompt，主要 TBT SLO 为 P99 150ms。P/D 分离实验使用8 GPU。
- **作者报告结果：** 对 Qwen3-8B 和 DeepSeek-V4-Flash，SLO goodput 为最强基线的2.4–2.9倍；对 DeepSeek-V2-Lite 至少4.4倍。8 GPU P/D 分离实验中，满足 SLO 的请求比例约35%，基线约15–16%。
- **局限：** 校准对负载分布变化存在滞后，持续高负载时最长 Prompt 仍可能超时；P/D 分离只评估一种节点/引擎配置。未在论文中发现公开代码仓库链接，尚无第三方复现。
- **独立判断：** 该工作把优化目标从平均吞吐转向请求级 P99 TBT 与 SLO goodput，特别适合长输出、语音、Coding Agent 和多轮 Agent Serving。应关注代码是否发布，以及在 SGLang、不同 GPU 和真实多租户负载下能否复现。
- **来源：** [arXiv 页面与全文](https://arxiv.org/html/2611.18392v1)。

## 二、今日产业与学术判断

1. **Agent 产品竞争正从“能否调用工具”转向“能否安全地运行真实业务”。** Genpact Onyx 以流程知识和异常经验构建领域上下文；Anthropic 的 Managed Agents 将 Harness、Sandbox、凭据和会话历史纳入平台；Poki 则把控制面延伸到真实移动设备。产品差异开始集中在权限、审计、人工审批、状态恢复和业务责任，而不是简单的 Tool Calling。
2. **Memory 正从向量检索向结构化、可验证、保留来源的知识层演进。** Graphon 试图把对象存储、混合检索和引用回答合并；MEM-SQL 则把已验证 SQL 变成可复用的计算结构，并通过 coverage gate 防止“检索到了相似内容就误以为证据充分”。两者分别代表通用多模态存储层和领域结构化记忆层。
3. **Agent Inference 的关键指标正在从平均吞吐转向长会话下的尾延迟。** VelServe 说明少量 decode jitter 会沿着长输出放大为请求级 SLO 违约；未来 KV Cache、Prefill/Decode 调度和会话路由应共同优化 P99 TBT、TTFT、缓存命中和任务完成时间。
4. **模型能力与产品交付的边界正在分化。** Qwen4-Max 提供高上下文 API，但私有化部署、微调和生产数据治理仍是独立问题；企业客户最终购买的是可控的数据通路、审计、流程适配和稳定 SLA，而不只是模型参数规模。

## 三、Agent 专项观察

Agent 专项作为独立主线，本日有以下信号：

- **Agent 产品/企业运行时：** Genpact Onyx 已宣布可用；Anthropic 于11月12日发布 Self-hosted Claude Managed Agents 私有 Beta，可将 Harness、Sandbox、凭据、Session History、数据库和 Worker 全部运行在客户云或本地环境，模型请求可路由到 Anthropic、Amazon Bedrock、Google Agent Platform、Microsoft Foundry 或自有 Gateway。其安全设计强调 Brain/Hands 分离、凭据不进入 Sandbox、网络 Allowlist 和 OpenTelemetry 全轨迹导出。
- **垂直行业 Agent：** Anthropic 的 Claude for Manufacturing 提供17项 Skills 和4个 Connector（Autodesk Fusion、Infor、Microsoft 365、Oracle NetSuite），重点是报价、质量报告、设备故障诊断和供应商询价；官方强调在输出到客户/供应商前由人审阅，且该插件不直接操作生产设备。
- **工作空间与 Data Agent：** Claude Whiteboards、Sheets 于11月10日进入 Beta；Claude Data 同日从 Dashboard 更名并转为 GA，支持 Redshift、BigQuery、ClickHouse 等数据源，Certified Queries 和 Live Sharing 仍为 Beta。其定位是把分析、协作和数据故事留在 Claude 内，而不只是生成一次性回答。
- **Agent Memory/Context：** Graphon 提供可供 Claude Code、ChatGPT、Codex、Cursor 和 VS Code 使用的远程 MCP Server；OAuth 角色和 API Key 最小权限值得关注，但 Agent Memory 产品成熟度仍需与其对象存储/检索 API 分开评估。
- **Agent Harness 研究：** ModHarness-RL（arXiv，2026-11-13）将 Agent Harness 表示为运行在 typed State 上的 Compression 与 Steering 程序：从轨迹提出候选程序、执行验证、回放历史轨迹，再用 held-out gate 决定是否安装。论文在 CodeSearch 上相对固定 Harness 的平均提升约19%；实验使用8张 H100、GRPO 训练200步，模型覆盖 Qwen3、Qwen2.5、Qwen3.5。限制是 CodeSearch 做了最完整的基线比较，ALFWorld/BIRD SQL 主要验证模块泛化；程序由 GPT-5-mini 生成，论文未给出公开代码链接，确定性规则对开放式对话的适用性较弱。 [论文全文](https://arxiv.org/html/2611.18533v1)
- **开源生态抽检：** 对 LangGraph、Dify、Mem0、Letta、LlamaIndex 的最新提交做了样本检查，近期变化以依赖、测试、文档或修复为主；本窗口未发现足以入选重点的全新架构级 Release。抽样链接：[LangGraph](https://github.com/langchain-ai/langgraph/commits/main/)；[Dify](https://github.com/langgenius/dify/commits/main/)；[Mem0](https://github.com/mem0ai/mem0/commits/main/)；[Letta](https://github.com/letta-ai/letta/commits/main/)；[LlamaIndex](https://github.com/run-llama/llama_index/commits/main/)。
- **安全治理判断：** Self-hosted Managed Agents 的控制面隔离、凭据代理、网络 Allowlist 和 OTEL Trace 是较完整的运行时安全基础；但这些能力仍不能自动解决每个 Tool 的业务授权、SQL 写操作审批、事务边界、回滚和 Prompt Injection。对企业 Agent，必须把模型决策、工具授权和数据变更的责任边界分别设计。

## 六、观察盲区与证据限制

1. **中国数据库与云厂商：** 本窗口内可核验的中国重大进展以 Qwen4-Max 为主；未找到足以进入重点榜单的国产数据库内核、云数据库或数据工程平台新版本发布。不能将旧发布会、路线图或招聘信息包装成当日新增。
2. **数据库与 Data Engineering：** ClickHouse、Snowflake、Databricks、Neon、DuckDB 等种子对象未发现本窗口内足以进入重点榜单的架构级新增；本期以 MEM-SQL 研究作为 AI × Database 的主要信号。
3. **开源项目：** Poki 是本期较明确的新产品型开源项目；对常见 Agent/Memory 仓库的提交抽检未发现足以入选的重大新 Release。抽样不等于完整扫描全 GitHub，Stars 也未作为质量判断依据。
4. **商业证据：** Genpact Onyx、Graphon 的公开资料仍缺少产品专属的价格、合同金额、客户部署规模和独立 ROI。Graphon 的 ATM-Bench 结果可追溯，但属于单次公开基准运行；Genpact 活动客户名单不等于 Onyx 付费客户名单。
5. **学术证据：** MEM-SQL、VelServe、ModHarness-RL 均为11月13日 arXiv 预印本，不是同行评审成果。MEM-SQL 和 VelServe 未发现公开 Artifact/代码链接；ModHarness-RL 的主要对照实验集中在 CodeSearch，其他环境主要验证模块泛化。论文数字均为作者实验，不是第三方复现或生产证据。
6. **覆盖限制：** 本报告对公开产品页、官方公告、论文全文、会议官网和少量 GitHub 仓库做了核验；没有覆盖所有私有融资数据库、付费客户合同、内部部署数据和全部代码提交。对缺乏可靠公开证据的方向明确留空，不为满足八大领域和 Agent 专项覆盖要求而凑数。

---
**本期结论：** 最值得继续追踪的组合是 Qwen4-Max 的长上下文 API、Genpact Onyx 的流程型 Agent、Poki 的设备端 Computer Use、Graphon 的存储/记忆一体化，以及 MEM-SQL/VelServe 对“可验证历史知识”和“尾延迟 SLO”的系统化处理。短期内应优先验证真实部署、权限边界、成本和可复现性，而不是只比较模型参数、融资金额或厂商演示。
